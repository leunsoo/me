다국어에서 어려운 건 문자열을 번역하는 게 아니다 — **언어를 URL 어디에 둘 것인가**, 그리고 **번역 파일을 클라이언트로 안 보내면서 정적 렌더를 유지**하는 것이다.

## 왜 URL 에 언어를 넣나

`/ko/about`, `/en/about` — 언어를 경로 세그먼트로 둔다.

- **언어마다 진짜 URL** → 구글이 각각 인덱싱, 링크를 공유하면 상대 브라우저 설정과 무관하게 그 언어, CDN 이 URL 단위로 캐시.
- **라우트 파라미터** → `generateStaticParams` 로 빌드 때 두 언어를 미리 생성.

쿠키로만 언어를 정하면 URL 은 하나뿐 — 방문자마다 내용이 바뀌어 정적 생성도, 언어별 인덱싱도 못 한다.

## 구조: `app/[locale]/`

모든 라우트를 `[locale]` 아래로 옮긴다. `app/[locale]/layout.tsx` 가 루트 레이아웃이고 `<html lang={locale}>` 를 여기서 만든다.

```tsx
// app/[locale]/layout.tsx
export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale })); // [{locale:'ko'},{locale:'en'}]
}

export default async function LocaleLayout({ children, params }) {
  const { locale } = await params;
  if (!hasLocale(routing.locales, locale)) notFound();
  return (
    <html lang={locale}>
      <body>
        <NextIntlClientProvider>{/* … */}</NextIntlClientProvider>
      </body>
    </html>
  );
}
```

`generateStaticParams` 가 로케일 목록을 반환하면 빌드가 `/ko/*`, `/en/*` 를 각각 프리렌더한다.

## 감지와 리다이렉트: `proxy.ts`

Next 16 에서 `middleware` 가 `proxy` 로 개명됐다. `next-intl` 의 `createMiddleware` 를 그대로 export 한다.

```ts
// src/proxy.ts
import createMiddleware from "next-intl/middleware";
import { routing } from "./i18n/routing";

export default createMiddleware(routing);
export const config = { matcher: "/((?!_next|_vercel|.*\\..*).*)" };
```

언어 없는 요청(`/`, `/about`)이 오면 `Accept-Language` 헤더 협상 + `NEXT_LOCALE` 쿠키를 보고 `/ko` 또는 `/en` 으로 307 리다이렉트한다. 언어를 전환하면 선택을 쿠키에 저장한다. **감지는 렌더 전에 한 번**, 페이지 코드로 새지 않는다.

## 메시지 카탈로그

언어별 JSON. 네임스페이스로 중첩한다.

```json
// messages/ko.json
{
  "nav": { "workshop": "작업실", "blog": "블로그", "about": "소개" },
  "hero": { "headline": "코드 강박", "tagline": "…" }
}
```

```tsx
// 서버 컴포넌트
const t = await getTranslations("hero");
<h1>{t("headline")}</h1>;

// 클라이언트 컴포넌트 (NextIntlClientProvider 아래)
const t = useTranslations("nav");
<Link href="/workshop">{t("workshop")}</Link>;
```

`getRequestConfig` 가 요청마다 해당 언어 파일을 로드한다.

```ts
// src/i18n/request.ts
export default getRequestConfig(async () => {
  const requested = await getRootLocale(); // 아래 next/root-params
  const locale = hasLocale(routing.locales, requested)
    ? requested
    : routing.defaultLocale;
  return {
    locale,
    messages: (await import(`../messages/${locale}.json`)).default,
  };
});
```

이 `import` 는 **서버에서만** 실행된다. 번역 파일이 수백 KB 가 돼도 클라이언트 번들엔 안 들어간다 — 서버 컴포넌트는 이미 문자열을 박아 HTML 로 보내고, 클라이언트 컴포넌트엔 `NextIntlClientProvider` 가 **참조된 네임스페이스만** 직렬화해 내려준다.

## 로케일을 어디서나: `next/root-params`

Next 16 신규. 루트 세그먼트가 `[locale]` 이면 아무 서버 컴포넌트·유틸에서 prop 없이 읽는다.

```ts
import { locale } from "next/root-params";
const current = await locale(); // "ko" | "en"
```

`request.ts` 가 이걸로 로케일을 해석한다. 그래서 **페이지마다 `params` 를 받아 `setRequestLocale(locale)` 를 부르는 보일러플레이트가 없다.** (`setRequestLocale` 는 next-intl 4.14 에서 `@deprecated`, root-params 로 이관 권장.)

부수 효과 하나 더 — 헤더를 읽지 않으므로 페이지가 **정적으로** 유지된다. `cookies()` 나 `headers()` 를 레이아웃에서 부르면 그 순간 동적 렌더로 떨어진다.

## 로케일 인식 네비게이션

`next/link` 대신 `createNavigation` 이 만든 것을 쓴다.

```ts
// src/i18n/navigation.ts
export const { Link, redirect, usePathname, useRouter } =
  createNavigation(routing);
```

- `<Link href="/workshop">` → 현재 로케일을 붙여 `/ko/workshop` 로.
- `usePathname()` → 반대로 로케일 접두사를 **뗀** `/workshop` 을 돌려줌 → 활성 링크 판별이 그대로 된다.

언어 전환 버튼:

```tsx
const pathname = usePathname(); // "/workshop"
router.replace(pathname, { locale: next }); // → "/en/workshop", NEXT_LOCALE 쿠키 갱신
```

같은 페이지를 유지하며 언어만 바꾼다. `replace` 라 히스토리에 안 쌓인다.

## 설정

```ts
// next.config.ts
const withNextIntl = createNextIntlPlugin(); // src/i18n/request.ts 자동 인식
export default withNextIntl(nextConfig);
```

```ts
// src/i18n/routing.ts
export const routing = defineRouting({
  locales: ["ko", "en"],
  defaultLocale: "ko",
  localePrefix: "always", // 둘 다 접두사. /ko, /en
});
```

## 정리: 사용한 기술

| 기술 | 역할 |
| --- | --- |
| `next-intl` 4.14 | 메시지·라우팅·미들웨어·ICU 포맷 |
| `[locale]` 동적 세그먼트 | 언어별 URL + `generateStaticParams` 로 정적 생성 |
| `proxy.ts` (구 middleware) | `Accept-Language` + 쿠키로 감지 → 307 리다이렉트 |
| `NEXT_LOCALE` 쿠키 | 전환한 언어 기억 |
| `next/root-params` | prop 없이 로케일 해석 → `setRequestLocale` 제거, 정적 유지 |
| `getRequestConfig` | 요청마다 `messages/*.json` 서버 로드 (클라 번들 제외) |
| `getTranslations` / `useTranslations` | 서버 / 클라이언트 번역 조회 |
| `NextIntlClientProvider` | 참조된 네임스페이스만 클라이언트로 직렬화 |
| `createNavigation` | 로케일 인식 `Link` · `usePathname` · `useRouter` |
| `<html lang={locale}>` | 스크린리더·브라우저 번역 프롬프트용 언어 표시 |

관련 파일: `src/i18n/{routing,navigation,request}.ts`, `src/proxy.ts`, `src/messages/*.json`, `src/app/[locale]/layout.tsx`, `src/components/ui/LocaleSwitcher.tsx`.

로케일을 바꾸면 `[locale]` 이 달라지며 루트 레이아웃이 리렌더된다 — [다크 모드](/workshop/dark-mode) 글에서 깜빡임 방지 스크립트를 인라인이 아니라 외부 파일로 뺀 이유가 이것이다.
