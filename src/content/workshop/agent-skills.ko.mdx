## 코드 작성 원칙

### ponytail

실제로 동작하는 한도 안에서 가장 단순하고 짧고 최소한인 해결책을 강제한다.\
이 작업이 애초에 필요한지(YAGNI)부터 따지고, 커스텀 코드보다 표준 라이브러리를, 의존성보다 네이티브 플랫폼 기능을, 여러 줄보다 한 줄을 지향한다.\
코드를 작성·추가·리팩터·수정·리뷰·설계하는 모든 작업과 라이브러리·의존성 선택에 적용되며, lite·full(기본)·ultra 세 강도를 지원한다.

아래 세 개는 ponytail의 파생 스킬로, 원칙을 지키는지 확인하는 역할을 나눠 맡는다.

- **ponytail-review**

  과설계만 전문적으로 다루는 코드 리뷰.\
  지금 만든 diff만 검토해서, 재발명된 표준 라이브러리, 불필요한 의존성, 투기적 추상화, 죽은 유연성처럼 지울 수 있는 것을 찾아, 발견마다 위치·자를 것·대체할 것을 한 줄로 정리한다.

- **ponytail-audit**

  ponytail-review와 같지만 범위가 diff가 아니라 저장소 전체다.\
  지울 것·단순화할 것·표준 라이브러리나 네이티브 기능으로 대체할 것을 순위를 매겨 보고한다.

- **ponytail-debt**

  코드베이스에 남은 모든 `ponytail:` 기술 부채 주석을 모아 목록으로 보여준다.\
  의도적으로 작성했던 기술 부채들이 추후 방치되지 않도록, 아무것도 바꾸지 않고 한 번 보고하는 형태로 동작한다.

## 컴포넌트 설계

### vercel-composition-patterns

확장 가능한 React 조합 패턴이다.\
boolean prop이 늘어나는 컴포넌트를 리팩터링하거나, 유연한 컴포넌트 라이브러리를 만들거나, 재사용 가능한 API를 설계할 때 쓴다.\
compound component, render props, context provider, 컴포넌트 아키텍처 관련 작업에서 발동하며 React 19 API 변화도 다룬다.

## 웹 품질

### accessibility

WCAG 2.2 가이드라인을 기준으로 웹 접근성을 점검하고 개선한다.\
접근성 향상, a11y 감사, WCAG 준수, 스크린 리더 지원, 키보드 내비게이션이 필요할 때 쓴다.

### performance

더 빠른 로딩과 나은 사용자 경험을 위해 웹 성능을 최적화한다.\
사이트 속도 개선, 로드 시간 단축, 페이지 속도 개선, 성능 감사가 필요할 때 쓴다.

### seo

검색엔진 노출과 순위를 위해 최적화한다.\
메타 태그 수정, 구조화 데이터 추가, 사이트맵 최적화가 필요할 때 쓴다.

## 디자인

### frontend-design

새 UI를 만들거나 기존 UI를 다시 잡을 때 의도적이고 개성 있는 비주얼 디자인을 위한 가이드를 제공한다.\
미적 방향과 타이포그래피를 잡아, 템플릿 기본값처럼 보이지 않는 선택을 돕는다.

## 스킬 업데이트

각 스킬은 외부 저장소에서 가져온 것이라 추후 최신 버전과 어긋난다.\
이를 GitHub workflow 스케줄링으로 각 스킬의 최신 버전을 확인하여, 변경 사항이 있으면 pull request를 생성한다.\
이 PR은 자동으로 병합되지 않고, 내용을 확인한 뒤 직접 병합한다.
