**MDX = Markdown + JSX.** 평범한 마크다운 문서 안에 리액트(또는 다른 JSX) 컴포넌트를 그대로 써넣을 수 있는 형식이다. 확장자는 `.mdx`.

```mdx
# 이번 분기 지표

지난달 대비 우상향이다.

<BarChart data={sales} />

**결론**: 계획대로.
```

`#`, `**`는 평소처럼 마크다운으로 변환되고, `<BarChart />`는 실제로 렌더되는 컴포넌트다.

## 왜 쓰나

일반 마크다운은 글쓰기엔 좋지만 "여기에 인터랙티브한 예제를 넣고 싶다"가 안 된다. 그렇다고 HTML로 직접 쓰면 글이 마크업 범벅이 된다. MDX는 그 중간이다 — **산문은 산문대로 쓰고, 필요한 지점에만 컴포넌트를 박는다.** 기술 블로그, 문서 사이트, 디자인 시스템 문서에서 흔히 쓴다.

## 문법

### 마크다운은 그대로

제목 `#`, 굵게 `**`, 목록 `-`, 링크 `[텍스트](url)`, 인라인 코드는 백틱, 코드 블록은 펜스(백틱 세 개). `remark-gfm` 플러그인을 붙이면 표·취소선·체크리스트도 된다.

### 컴포넌트

```mdx
import { Callout } from './Callout'

<Callout type="warning">
  이 안에서도 **마크다운**이 동작한다.
</Callout>
```

컴포넌트가 스코프에 있어야 한다 — 파일 안에서 직접 `import` 하거나, 렌더러에 "컴포넌트 맵"으로 넘겨준다.

### 표현식 `{ }`

```mdx
2 + 2 = {2 + 2}

export const author = '이은수'

글쓴이: {author}
```

중괄호 안은 그냥 JavaScript다.

### Frontmatter

파일 맨 위 `---`로 감싼 YAML 블록. 제목·날짜·태그 같은 메타데이터를 담는다. MDX 자체 기능은 아니고, 파싱하는 쪽(`gray-matter` 등)이 떼어내 처리한다.

```mdx
---
title: "MDX 입문"
date: "2026-01-01"
tags: [react, markdown]
---

여기부터 본문.
```

## 어떻게 렌더되나

MDX 컴파일러가 `.mdx`를 **리액트 컴포넌트를 export 하는 JS 모듈**로 바꾼다. 중간에 두 지점에서 개입할 수 있다:

- **remark 플러그인** — 마크다운 단계. 예: `remark-gfm`(표 지원)
- **rehype 플러그인** — HTML 트리 단계. 예: `rehype-slug`(제목에 id), `rehype-pretty-code`(코드 하이라이트)

## Next.js에서 쓰는 두 가지 방식

| 방식 | 형태 | 언제 |
| --- | --- | --- |
| **파일 = 페이지** | `@next/mdx` 설정 후 `app/about/page.mdx` | 페이지 하나가 통째로 글일 때 |
| **콘텐츠 컬렉션** | `content/`에 `.mdx`를 모아두고 코드가 스캔 | 글이 여러 개, 동적 라우트로 뿌릴 때 (블로그) |

컬렉션 방식은 다시 두 갈래다. **직접** — `fs`로 폴더 읽기 + `gray-matter`로 frontmatter + `next-mdx-remote`로 본문 렌더. **툴** — `Contentlayer`·`Velite`가 스캔·타입 생성·스키마 검증까지 대신 해준다.

## 주의점

- **`<` 와 `{` 는 특수문자다.** 본문에 그냥 쓰면 JSX/표현식으로 해석된다. 리터럴로 남기려면 백틱이나 코드 펜스 안에 넣는다.
- **컴포넌트는 서버/클라이언트 구분을 따른다.** 서버 컴포넌트로 렌더하면 MDX 안의 컴포넌트도 서버 컴포넌트여야 한다. `useState` 등을 쓰려면 그 컴포넌트에 `"use client"`.
- **스타일이 샌다.** 글 전체에 `.prose` 같은 스타일을 걸면, 본문에 임베드한 컴포넌트 내부까지 그 스타일이 새어든다. `not-prose` 같은 탈출 클래스로 막는다.
- **일반 `.md`로 충분하면 그걸 쓴다.** 인터랙티브 요소가 없으면 MDX는 과하다.
